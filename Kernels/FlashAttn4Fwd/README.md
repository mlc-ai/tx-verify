# FlashAttention-4 forward (CuTeDSL), symbolic shape

The kernel is proved: [Theorem.lean](Theorem.lean) exports `correct` (safe, progress, terminates
and the attention output of `Post`), `completed_execution` and `realizable_result` for every
launch that satisfies `Pre` ([Spec.lean](Spec.lean)), under the kernel assumptions
`Assumptions.all` ([Assumptions.lean](Assumptions.lean), with the software `exp2` template in
[Assumptions/Exp2Template.lean](Assumptions/Exp2Template.lean), justified in
[DECISIONS.md](DECISIONS.md)). `Theorem.lean` also lists the readings of the specification the
result depends on. The directory name keeps the shape of the instance the PTX was generated
from; it is not the proof scope.

## Verification target

- Source: Dao-AILab/flash-attention `flash_attn/cute/flash_fwd_sm100.py`
  (`FlashAttentionForwardSm100`, BSD-3-Clause); the commit is recorded in [manifest.json](manifest.json).
- [flash_fwd_sm100.ptx](flash_fwd_sm100.ptx): 4897 instructions generated by CuTeDSL,
  with the SHA256 recorded in the manifest; no PTX string rewriting.
- Generation instance (`config` in the manifest): batch 1, sequence length 8192, 32 Q/KV heads,
  head dimension 128, non-causal, fp16, `sm_100a`. These values only size the input tensors
  `gen_ptx.py` passes to `flash_attn_func` (default `num_splits=1`, no LSE); they are not the proof scope.
- [Ptx.lean](Ptx.lean): generated by `Tools/export_lean.py`; freshness is checked by
  `tests/test_semantics.py`.

## Scope of the proof

Fixed by the PTX: head dimension 128, fp16, non-causal, no LSE output, `seqlen_q > 256`,
block 512 threads, cluster (2, 1, 1). Parameters (`scope` in the manifest):

- batch: any;
- heads: any, with `h_q = h_kv`;
- `seqlen_q`: any multiple of 512; `seqlen_k`: any multiple of 128; they may differ;
- grid: any even number of CTAs.

Sequence lengths of arbitrary value are a later step (masks taking effect, TMA out-of-bounds
fill and truncation, the `-inf` numeric path). `seqlen_q <= 256`, GQA/MQA, returning LSE and
causal masking compile to a different PTX and are separate verification targets.

## Why one PTX covers the scope

This is read from the source and the PTX; it has not been confirmed by regenerating with other
shapes. To confirm: run `gen_ptx.py` with several (batch, seqlen_q, seqlen_k, heads) in scope
and compare the PTX byte for byte with the checked-in file.

- Shape is a runtime parameter. The CuTeDSL compile cache key
  (`flash_attn/cute/interface.py:732-779`) holds dtype, head dim, `qhead_per_kvhead`, `causal`,
  `lse is None`, tile sizes, `use_2cta_instrs` and other options, but no batch, sequence length or
  head count; the tensors are made with `mark_layout_dynamic` (`flash_attn/cute/cute_dsl_utils.py:81-84`).
- The 2-CTA kernel is selected by `interface.py:589-603` (non-causal, head dim 128, no split-KV,
  `seqlen_q_packgqa > 2 * tile_m`, i.e. `seqlen_q > 256`); `q_stage = 2` needs `seqlen_q > 128`
  (`interface.py:559`). `num_splits` defaults to 1 in `flash_attn_func`, so the split-KV heuristic
  (`interface.py:571-572`) is not consulted. `pack_gqa` is off when `h_q = h_kv`
  (`interface.py:462-463`).
- The kernel reads shape-dependent scalars from only these parameters:
  `param_1` first 32-bit word (PTX:41), `param_11` and `param_12` (PTX:46-51, 12-byte
  FastDivmod parameters) and `param_13` (PTX:251, 711, 1525, 1617, 4519). By field order of
  `StaticPersistentTileScheduler.Params` (`tile_scheduler.py:289-293`), `param_11` is the
  divmod by `num_block_cluster`, `param_12` the divmod by `num_head`, `param_13`
  `total_blocks_cluster`; `param_1` is the K tensor, whose first extent is `seqlen_k`. The
  parameter-to-field assignment is by this order and was not checked against the launch ABI.
- `seqlen_q` reaches the kernel only through the scheduler parameters and the Q/O TMA
  descriptors; `head_dim` appears only as compile-time constants and in descriptors.

## Launch and tensor maps as functions of the shape

Let `s_q`, `s_k` be the sequence lengths, `h` the head count, `b` the batch.

| Quantity | Value | Source |
| --- | --- | --- |
| `num_block` | `ceil(s_q / 256)` (`q_stage * m_block_size = 2 * 128`) | `flash_fwd_sm100.py:174, 651-653` |
| `num_block_cluster` | `ceil(num_block / 2)` | `tile_scheduler.py:299` |
| `total_blocks_cluster` | `num_block_cluster * h * b` | `tile_scheduler.py:300` |
| grid | `(min((SMs // 2) * 2, total_blocks_cluster * 2), 1, 1)` | `tile_scheduler.py:346-348` |
| block, cluster | `(512, 1, 1)`, `(2, 1, 1)` | `flash_fwd_sm100.py:181, 272-290, 787-790`; PTX `.reqntid 512, 1, 1` |
| work item (one cluster) | `(batch, head, 512 rows of Q)`: `divmod(cluster_idx, num_block_cluster)` then `divmod(., h)`; persistent, stride `cluster_dim` | `tile_scheduler.py:350-368` |
| KV loop trips | `ceil(s_k / 128)` (`tile_n = 128`) | `block_info.py:31` (non-causal) |

Tensor maps (`param_4`..`param_7`, 128 bytes each, in the order Q, K, V, O of the atoms in
`flash_fwd_sm100.py:762-765`), as stated in [Data/TensorMaps.lean](Data/TensorMaps.lean) and
DECISIONS D-TMAP-BOX. Each map is rank 4 with the head dimension first, the order of the
coordinates `{d, row, head, batch}` of every `cp.async.bulk.tensor.4d` in the PTX (for V the
CuTe view is transposed, but its TMA dimension 0 is still the contiguous head dimension):

| Map | Extents (dim 0 to 3) | Box (dim 0 to 3) |
| --- | --- | --- |
| Q | `(128, s_q, h, b)` | `64 x 128 x 1 x 1` |
| K | `(128, s_k, h, b)` | `64 x 64 x 1 x 1` |
| V | `(128, s_k, h, b)` | `64 x 128 x 1 x 1` |
| O | `(128, s_q, h, b)` | `64 x 128 x 1 x 1` |

All maps are f16 with 128-byte swizzle and unit traversal strides; the byte strides of
dimensions 1 to 3 are `256 h`, `256` and `256 h rows`. The boxes are derived from the PTX
(head-dimension coordinates 0 and 64 only, the distances between the shared destinations of one
copy, and the expected transaction bytes); they are launch obligations, not values read from the
host-built descriptors. The out-of-bounds fill mode and the allocation class are unconstrained
parameters (D-TMAP-UNKNOWN).

## Decode coverage

`lake build Kernels.FlashAttn4Fwd.Coverage` prints a report by instruction form.
Currently, all 4897 instructions are decoded.

Parameter declarations (`.param .align 4 .b8 name[16]`), `.reqntid`, the `ld.param` reads of
by-value parameter objects (`ld.param.b32` at offsets 0 and 4, `ld.param.v2.b8` into `.b16`
registers) and the comma-list register declarations of the inline assembly scopes
(`.reg .b32 a, b`) are decoded. A `ld.param` read of a parameter object needs the object's
bytes in `Launch.paramBytes` (EXT-LAUNCH). The predicate logic (`not.pred`, `and.pred`) and
integer forms (`mul.hi.u32`, `shr.s32`, `mul.wide.u16`, `max.s32`) are decoded with exact
semantics (THREAD-INT; DEC-PRED-LOGIC, DEC-INT-FORMS). The floating forms (`add`, `sub`,
`fma` of `.f32x2`, `sub.f32`, two- and three-input `max.f32`, `setp.{ge,lt,ne,neu}.f32`,
`ex2.approx.ftz.f32`, `rcp.approx.ftz.f32`) are decoded only: Core gives them no rule. The
kernel assumptions give them their meaning: `idealArith` the `.rn` forms, `max` and the
comparisons, including a comparison with the `-inf` constant (`setpInf`); `approx` the
`ex2.approx` and `rcp.approx`; `swExp2` the software `exp2` sequences, which contain
`add.rm.f32x2` (DEC-FLOAT-FORMS, ASM-A0 to ASM-A3; see Numerics).

The tensor loads with `.L2::cache_hint` (`cp.async.bulk.tensor.4d ... .L2::cache_hint.cta_group::2`,
10) share the existing tensor-load rule; the 64-bit cache policy is read as a defined value and
otherwise has no effect (DEC-TENSOR-CACHE-HINT). Their mbarrier operand, computed by clearing bit
24 of a shared address with `and.b32`, has no meaning in Core and needs an FA4 Assumption. The 64
`tcgen05.mma.cta_group::2.kind::f16` decode: without the lane-mask operand (every lane written),
with a constant `enable-input-d` (§4.5.3), and, for the PV MMAs, with A in Tensor Memory at
`[tmem_a + imm]` (the offset added to the column index, THREAD-TC) laid out as D's Layout A (EXT-TCFIG); MN-major V and
the K steps inside the 128-byte swizzle atom are the existing shared-address rules (DEC-MMA-FORMS).
The TMA stores with `.L2::cache_hint` and the multicast `tcgen05.commit` (mask 3) were already
decoded.

The synchronization forms are decoded with their Core semantics. `mbarrier.arrive.shared.b64`
and `mbarrier.arrive.expect_tx.shared.b64` with a state register are the existing `.shared::cta`
arrival rule; the state register holds no value afterwards, so reading it would fault
(DEC-MBAR-STATE; FA4 never reads it). `vote.sync.ballot.b32` with the full member mask is a warp
ballot instance (DEP-WARP-VOTE, DEC-VOTE-BALLOT). `bar.arrive` is an arrival of the existing named
CTA barrier that counts in the generation, does not wait for the other warps, and orders the
arriving thread's earlier accesses before the accesses after a `bar.sync` of the same generation
(OBJ-CTA-BARRIER-SYNC, DEC-BAR-ARRIVE). Barrier 2 is reached from several source positions
in one generation, and warpgroup 3 makes its `setmaxnreg.dec 72` from four; Core compares the
warps of one generation or request by barrier name and count, or by direction and count, not by
position (EXT-BAR-PARTICIPANTS).

## Numerics

The floating computation is read as exact real arithmetic (`idealArith`), and the approximate
operations as the exact functions: `ex2.approx` and `rcp.approx` through `approx`, and the
software `exp2` (which rounds with `add.rm.f32x2` of `1.5 * 2^23` and clamps at `-127`) through
`swExp2`, whose function is `2 ^ x` (ASM-A2, ASM-A3; OPEN-NUM). These are human-reviewed
assumptions, not IEEE operations in Core. The row-max masking writes `-inf`
(`selp.f32 ..., 0fFF800000, ...`) and compares with it (`setp.neu.f32 ..., 0fFF800000`). The
comparison is read in the extended reals (`setpInf`, ASM-A1). Any other read of `-inf` by a
floating instruction would fault, and `correct` includes safety, so in scope no other floating
instruction reads it.

## Regenerate

Regenerate with an SM100 GPU and the toolchain versions pinned in the manifest:

```bash
CUDA_VISIBLE_DEVICES=<gpu> python gen_ptx.py --flash-attention <checkout>
python ../../Tools/export_lean.py flash_fwd_sm100.ptx -o Ptx.lean \
  --namespace PTX.Generated.FlashAttn4Fwd
```
